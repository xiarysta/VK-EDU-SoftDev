# Задание №6

## Команда MVP

| Роль | Зоны ответственности |
| --- | --- |
| **Product Manager / Scrum Master** | Определяет приоритеты MVP и собирает обратную связь агентств. Организует встречи и помогает устранять препятствия в работе команды. |
| **UX/UI Designer / Аналитик** | Уточняет требования и сценарии менеджера агентства. Проектирует форму параметров поездки и редактор маршрута. |
| **Frontend Developer** | Реализует интерфейс на React + TypeScript. Обеспечивает взаимодействие с серверным API. |
| **Backend Developer / Tech Lead** | Реализует API, хранение маршрутов и пересчёт стоимости. Отвечает за технические решения и интеграцию с Plantrip API. |
| **QA Engineer** | Проверяет сценарий создания, редактирования и сохранения маршрута. Проверяет обработку ошибок и корректность расчёта бюджета. |
| **DevOps Engineer — частичная занятость** | Настраивает развёртывание приложения. Обеспечивает сбор журналов ошибок и резервное копирование базы данных. |

## Методология разработки

Выбран **Scrum со спринтами по две недели**.

1. Обратная связь пилотных агентств после каждого спринта позволяет уточнять требования и приоритеты MVP.
2. Короткие итерации позволяют раньше проверить интеграцию с Plantrip API и обнаружить проблемы генерации маршрутов.
3. Общая цель спринта объединяет работу специалистов вокруг готового пользовательского сценария: от ввода параметров до сохранения маршрута.

## Встречи команды

| Встреча | Цель | Частота |
| --- | --- | --- |
| **Планирование спринта** | Определить цель спринта и выбрать задачи для её достижения. | Раз в две недели, в начале спринта. |
| **Ежедневный Scrum** | Оценить продвижение к цели спринта, выявить препятствия и согласовать ближайшие действия. | Каждый рабочий день, 15 минут. |
| **Обзор спринта** | Показать работающий результат представителям агентств и собрать обратную связь. | Раз в две недели, в конце спринта. |
| **Ретроспектива спринта** | Обсудить работу команды и выбрать улучшения процесса. | Раз в две недели, после обзора спринта. |
